1. Installing & Configuring Unity Cloud Save

Before writing any persistence code, you must install the Cloud Save SDK and enable the service in your Unity Gaming Services (UGS) project. Follow the official Unity Cloud Save Get Started documentation to set up your environment:

  1. Link your Unity Project: Open Edit > Project Settings > Services and verify that your project is linked to your Unity Cloud Organization and Project ID.
  2. Install the Cloud Save Package: Open Window > Package Manager, switch the registry filter to Unity Registry, search for Cloud Save (com.unity.services.cloudsave), and click Install. Installing this package automatically includes Unity Services Core.
  3. Verify Authentication Package: Ensure Authentication (com.unity.services.authentication) is also installed, as Cloud Save partitions all Player Data under a unique PlayerId.
  4. Initialize Services at Startup: Make sure your project calls UnityServices.InitializeAsync() and signs the player in (e.g., via AuthenticationService.Instance.SignInAnonymouslyAsync()) before loading or saving any inventory data, as covered in Chapter 3 and Exercise 8.

2. From Volatile Network State to Cloud Persistence

In previous exercises, we built a networked inventory backed by NetworkList<NetworkItem>. While NetworkList automatically replicates inventory changes across connected clients during an active session, it lives exclusively in volatile memory (RAM). Once the host disconnects or the game closes, all collected items vanish.

To retain player inventories between sessions, we store the serialized list in Unity Cloud Save Player Data (CloudSaveService.Instance.Data.Player) as a JSON key-value record.

Multiplayer Authority Rule (IsOwner)

When integrating Cloud Save with Netcode for GameObjects (NGO), keep a critical architectural rule in mind: CloudSaveService.Instance.Data.Player always reads and writes data for the locally authenticated player on that machine.

In a Host-Client setup, the Host instantiates a PlayerInventory component for every connected player. Therefore, only the local owner of each character (if (!IsOwner) return;) must load and upload its own inventory to Cloud Save. If the Host ran Cloud Save logic for remote player objects, it would overwrite its own cloud inventory with other players' items.

3. Implementing CloudSaveManager

The CloudSaveManager.cs script acts as a persistent singleton service responsible for communicating asynchronously with Unity Cloud Save. Below is the focused implementation containing only the methods required to load and save the player's inventory:


using System;
using System.Collections.Generic;
using System.Threading.Tasks;
using Unity.Services.CloudSave;
using Unity.Services.CloudSave.Models;
using UnityEngine;

public class CloudSaveManager : MonoBehaviour
{
    public static CloudSaveManager Instance { get; private set; }
    private const string InventoryKey = "inventory";
    private string currentInventoryWriteLock = null;

    private void Awake()
    {
        if (Instance != null && Instance != this)
        {
            Destroy(gameObject);
            return;
        }
        Instance = this;
        DontDestroyOnLoad(this);
    }

    #region SAVE DATA
    public async Task<bool> SaveInventoryAsync(List<NetworkItem> inventory)
    {
        try
        {
            var dataToSave = new Dictionary<string, SaveItem>
            {
                { InventoryKey, new SaveItem(inventory, currentInventoryWriteLock) }
            };

            Dictionary<string, string> result = await CloudSaveService.Instance.Data.Player.SaveAsync(dataToSave);
            currentInventoryWriteLock = result[InventoryKey];

            Debug.Log($"Inventory saved ({inventory.Count} stacks). New writeLock: {currentInventoryWriteLock}");
            return true;
        }
        catch (CloudSaveValidationException e)
        {
            Debug.LogWarning($"WriteLock conflict or validation saving inventory: {e.Message}");
        }
        catch (CloudSaveRateLimitedException e)
        {
            Debug.LogWarning($"Rate limit reached in Cloud Save: {e.Message}");
        }
        catch (CloudSaveException e)
        {
            Debug.LogError($"Cloud save error: {e}");
        }

        return false;
    }
    #endregion

    #region LOAD DATA
    // Loads from player data and deserializes it transforming it into List<NetworkItem>
    public async Task<List<NetworkItem>> LoadInventoryAsync()
    {
        try
        {
            var results = await CloudSaveService.Instance.Data.Player.LoadAsync(
                new HashSet<string> { InventoryKey }
            );

            if (results.TryGetValue(InventoryKey, out Item item))
            {
                currentInventoryWriteLock = item.WriteLock;
                return item.Value.GetAs<List<NetworkItem>>() ?? new List<NetworkItem>();
            }
        }
        catch (Exception e)
        {
            Debug.LogError($"Error loading inventory: {e}");
        }

        return new List<NetworkItem>();
    }
    #endregion
}

Key Mechanisms in CloudSaveManager

  • LoadInventoryAsync(): Queries the "inventory" key from Data.Player. If found, it stores the server's version token in currentInventoryWriteLock and automatically deserializes the JSON payload into a List<NetworkItem>. If the player is new and no record exists yet, it safely returns an empty list (leaving currentInventoryWriteLock as null).
  • Optimistic Concurrency with SaveItem & Write Locks: Instead of passing raw objects to SaveAsync (which blindly overwrites cloud data), SaveInventoryAsync wraps the list inside new SaveItem(inventory, currentInventoryWriteLock). Unity's backend compares the submitted token against the stored version: if they match, the save succeeds and returns a fresh writeLock; if another session modified the record concurrently, the server rejects the request with a CloudSaveValidationException to prevent lost updates.
  • Resilient Return Status & Exception Handling: The method catches CloudSaveValidationException (version conflicts or quota violations), CloudSaveRateLimitedException (exceeding request quotas), and general CloudSaveException network errors, returning false so the caller knows the save must be retried later.

4. The Dirty Flag Programming Pattern

A common mistake when adding cloud persistence to a game is calling SaveInventoryAsync() every single time the player picks up an item. In an action or multiplayer game where players rapidly collect coins or loot, saving immediately on every pickup creates two major issues:

  • Rate Limit Throttling: Unity Cloud Save enforces a default quota of 600 requests per minute per player. Rapid item pickups can quickly exhaust this quota and trigger CloudSaveRateLimitedException errors.
  • Redundant Network Overhead: Serializing and transmitting the entire inventory multiple times per second wastes bandwidth and battery life on mobile or browser clients.

Conversely, waiting to save only when the player clicks "Quit" is too risky: if the game crashes, the browser tab closes abruptly, or the internet disconnects, the entire session's progress is lost.

How Dirty Flag Solves This

The Dirty Flag pattern decouples fast, frequent changes in local memory from slow, expensive synchronization operations (such as disk I/O or cloud HTTP requests):

  1. Track State Changes with a Boolean Flag: Maintain a simple boolean variable (private bool isDirty = false;). Whenever the inventory is modified in RAM, we do not contact the cloud; we simply set isDirty = true, indicating that the local state has diverged from the cloud state ("dirty").
  2. Batch Synchronization on a Schedule: A background loop checks isDirty at a fixed interval (e.g., every 30.0f seconds). If isDirty is false, the loop does nothing—zero network traffic is generated when the inventory hasn't changed.
  3. Clear the Flag Only Upon Confirmation: When isDirty is true, we capture a snapshot of the inventory, upload it asynchronously, and clear the flag. If the upload fails due to a temporary network drop, we set isDirty = true again so the changes are preserved for the next save cycle.

*Note: We also pair isDirty with a second boolean guard, isSaving, to prevent a new save request from launching if a previous asynchronous upload is still in flight.

5. Updating PlayerInventory for Cloud Save

Now we upgrade PlayerInventory.cs so that it loads the player's saved items upon spawning in the network, reacts to server-authoritative inventory updates using the Dirty Flag pattern, and flushes pending changes periodically and upon application pause or exit:


using System.Collections;
using System.Collections.Generic;
using System.Threading.Tasks;
using Unity.Netcode;
using UnityEngine;

public class PlayerInventory : NetworkBehaviour
{
    public NetworkList<NetworkItem> Inventory;
    [SerializeField, Tooltip("Add all the items that the player can pick up.")] 
    private ItemData[] itemDatabase;
    
    private bool isDirty = false;
    private bool isSaving = false;
    private readonly float saveInterval = 30.0f;

    private void Awake()
    {
        Inventory = new NetworkList<NetworkItem>();
    }

    public override async void OnNetworkSpawn()
    {
        // Only owner manages its own Cloud Save
        if (!IsOwner) return;

        // 1. Load saved inventory
        List<NetworkItem> savedItems = await CloudSaveManager.Instance.LoadInventoryAsync();
        if (savedItems.Count > 0)
        {
            InitializeInventoryServerRpc(savedItems.ToArray());
        }

        // 2. Listen applied changes
        Inventory.OnListChanged += HandleInventoryChanged;

        // 3. Auto save 
        StartCoroutine(SaveInventoryCoroutine());
    }

    public override void OnNetworkDespawn()
    {
        if (IsOwner)
        {
            Inventory.OnListChanged -= HandleInventoryChanged;
        }
    }

    private void HandleInventoryChanged(NetworkListEvent<NetworkItem> changeEvent)
    {
        isDirty = true;
    }

    [Rpc(SendTo.Server)]
    private void InitializeInventoryServerRpc(NetworkItem[] initialItems)
    {
        Inventory.Clear();
        foreach (var item in initialItems)
        {
            Inventory.Add(item);
        }
    }

    [Rpc(SendTo.Server)]
    public void PickupItemRpc(uint pickedItemID, int amount, ulong networkObjectId)
    {
        // Stack items in the list
        bool found = false;
        for (int i = 0; i < Inventory.Count; i++)
        {
            if (Inventory[i].ItemID == pickedItemID)
            {
                NetworkItem updated = Inventory[i];
                updated.Amount += amount;
                Inventory[i] = updated; // This shoots network synchronization
                found = true;
                break;
            }
        }

        if (!found)
        {
            Inventory.Add(new NetworkItem
            {
                ItemID = pickedItemID,
                Amount = amount
            });
        }

        if (NetworkManager.Singleton.SpawnManager.SpawnedObjects.TryGetValue(networkObjectId, out NetworkObject itemToDespawn))
        {
            itemToDespawn.Despawn(false); // We don't destroy the game object
        }
    }

    private IEnumerator SaveInventoryCoroutine()
    {
        WaitForSeconds wait = new WaitForSeconds(saveInterval);
        while (true)
        {
            yield return wait;

            if (isDirty && !isSaving)
            {
                _ = FlushInventorySaveAsync(); // Discard the Task result cleanly
            }
        }
    }

    private async Task FlushInventorySaveAsync()
    {
        if (!isDirty || isSaving || CloudSaveManager.Instance == null) return;

        isSaving = true;
        isDirty = false;

        // Copy NetworkList to a standard List to serialize it
        List<NetworkItem> snapshot = new List<NetworkItem>(Inventory.Count);
        foreach (var item in Inventory)
        {
            snapshot.Add(item);
        }

        bool success = await CloudSaveManager.Instance.SaveInventoryAsync(snapshot);

        // In case of error, we will try to save next cycle
        if (!success)
        {
            isDirty = true;
        }

        isSaving = false;
    }

    private void OnApplicationPause(bool pauseStatus)
    {
        if (pauseStatus && IsOwner && isDirty)
        {
            _ = FlushInventorySaveAsync();
        }
    }

    private void OnApplicationQuit()
    {
        if (IsOwner && isDirty)
        {
            _ = FlushInventorySaveAsync();
        }
    }

    public void ShowInventory()
    {
        foreach (var networkItem in Inventory)
        {
            // Translate the ID to an item
            ItemData itemData = GetItemDataByID(networkItem.ItemID);
            
            Debug.Log($"I have {networkItem.Amount} of {itemData.ItemName}");
        }
    }

    private ItemData GetItemDataByID(uint id)
    {
        foreach (var item in itemDatabase)
        {
            if (item.ItemID == id) return item;
        }
        return null;
    }
}

Step-by-Step Breakdown of the Integration

  1. Initial Load & Server Sync (OnNetworkSpawn & InitializeInventoryServerRpc): When the local player spawns, the owner awaits LoadInventoryAsync(). Because only the server has write authority over a NetworkList, the client sends the downloaded items to the server via InitializeInventoryServerRpc, which populates Inventory and replicates it across the network. Notice we subscribe to Inventory.OnListChanged after triggering the initial load so we don't mark the freshly loaded data as dirty unnecessarily.
  2. Reactive Dirty Flag (HandleInventoryChanged): Whenever the server stacks an existing item or adds a new one inside PickupItemRpc, NGO replicates the change to the owner client and fires Inventory.OnListChanged, automatically setting isDirty = true.
  3. Periodic Auto-Save (SaveInventoryCoroutine & FlushInventorySaveAsync): Every 30.0f seconds, the coroutine checks if unsaved changes exist. Using C#'s discard operator (_ = FlushInventorySaveAsync();), it invokes the asynchronous save without blocking the coroutine or triggering compiler warnings. Because NetworkList<T> is a native Netcode container rather than a standard serializable collection, FlushInventorySaveAsync copies its elements into a List<NetworkItem> snapshot before passing it to CloudSaveManager.
  4. Lifecycle Safeguards (OnApplicationPause & OnApplicationQuit): If the player minimizes the game (critical on WebGL and mobile devices) or exits before the 30-second timer elapses, these Unity lifecycle callbacks immediately flush any dirty inventory changes to the cloud.

6. Scene Setup & Testing

  1. Add CloudSaveManager to the Scene: Create an empty GameObject named CloudSaveManager in your startup/lobby scene and attach CloudSaveManager.cs. Because it calls DontDestroyOnLoad(this), it will remain accessible when transitioning to your gameplay scene.
  2. Ensure Service Initialization: Confirm that UnityServices.InitializeAsync() and AuthenticationService.Instance.SignInAnonymouslyAsync() finish executing before spawning the player prefab.
  3. Verify Player Prefab Setup: Confirm your player prefab has PlayerInventory.cs attached and all collectible ItemData ScriptableObjects assigned to its itemDatabase array in the Inspector.
  4. Test Persistence: Enter Play Mode, start a Host session, pick up several items in the scene, and wait 30 seconds (or stop Play Mode) until you see Inventory saved (...) in the Console. Restart Play Mode and verify that your previously collected items are automatically restored from Unity Cloud Save.

Inspecting Player Data in the Unity Cloud Dashboard

You can inspect, edit, or delete the stored JSON inventory directly from your browser using the Unity Cloud Dashboard:

  1. Open the Dashboard: Go to cloud.unity.com and sign in with your Unity ID (alternatively, open Edit > Project Settings > Services in Unity and click Dashboard).
  2. Select Project & Environment: Choose your linked project from the top project switcher and verify that the active Environment (e.g., production) matches the environment configured in your Unity Editor.
  3. Navigate to Cloud Save > Player Data: In the left-hand navigation sidebar, open Products (or LiveOps) > Cloud Save, and select Player Data.
  4. Search by Player ID: Copy the PlayerId printed in the Unity Console when signing in (e.g., Signed in with PlayerId: ...), paste it into the Player ID search bar, and click Find Player.
  5. Inspect or Reset the Record: Locate the inventory key in the player's key-value table to inspect its serialized JSON array (ItemID and Amount entries), its Default access class, and its current Write Lock token. You can also delete the key from this panel to test how your game initializes a brand-new player.
